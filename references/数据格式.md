# 批次数据与命令接口

入口是 `python scripts/mlist.py <步骤>`。所有步骤接受 `--ws 路径`、`--json`，它们可放子命令前后；批次相关步骤还需 `--batch 名字`（`new-batch` 用位置参数名字）。

```text
python scripts/mlist.py init --ws "E:\店铺工作区"
python scripts/mlist.py new-batch 冬季一批 --ws "E:\店铺工作区"
python scripts/mlist.py price --ws "E:\店铺工作区" --batch 冬季一批
python scripts/mlist.py check --ws "E:\店铺工作区" --batch 冬季一批 --json
python scripts/mlist.py fill --ws "E:\店铺工作区" --batch 冬季一批
python scripts/mlist.py status --ws "E:\店铺工作区" --batch 冬季一批
```

工作区根目录有 `shop.json`、`template/`、`batches/`。每批次有下列文件，以及 `images/` 和 `output/`。初始化只建立空 CSV 表头和空 JSON，不把它们当作已完成的数据。

| 文件 | 格式和用途 |
|---|---|
| `barcodes.txt` | 每行一个条码字符串，保留前导零；`#` 开头为注释，条码后空格隔开的文字保留为备注。由 fetch 读取。 |
| `早上看这里.md` | `report --batch 批次` 离线生成的早晨报告：能否上传、完整分表路径、链接/SKU 数、售价利润、出图单位、审阅问题和 notes.md 全文。缺文件写“没做到这一步”。 |
| `yollgo.json` | fetch 保存的所有报价、所选商家和抓取时间，格式见后面的完整例子。 |
| `groups.json` | 人或 agent 判断后填写的分组和重量尺寸；由 build 校验，不自动猜颜色。 |
| `src/` | 每家报价的原图 `{shopId}-{artId}.jpg`；`_sheet.jpg` 是所选报价总览。已有原图不重下。 |
| `build.json` | build 生成的成本口径与候选表 SHA-256，供 price 检查完整性；不要手改。 |
| `candidates.csv` | 表头保持旧格式：`group,shop,art_id,ean,unit_ean,src_name,var1_name,var1_value,var2_name,var2_value,pack_qty,unit_cost_ex_iva,img_hash,weight_kg,len_cm,wid_cm,hei_cm,market_low,market_high,notes`。一行一个可售 SKU；店铺 id、货号和 EAN 都按字符串读。 |
| `priced.csv` | 保留候选全部列，追加 `real_cost,ship_est,billable_kg,price,original_price,profit_no_coupon,profit_with_coupon,min_safe_price,max_discount_pct,ean_valid,vs_market`。单位欧元，重量 kg；由 `price` 生成，候选改变后必须重做。 |
| `variantes.csv` | `group,art_id,ean,variante`，将每个 SKU 映射到图片文件夹。兼容旧的无 `ean` 表：按 group/art_id 对应全部候选条码；不同颜色应使用含 EAN 的显式格式。 |
| `content.json` | group 为键的西语文案和链接资料，字段见下。 |
| `overlays.json` | 图上精确文字及布局，group 下有 `slots`，支持 `inherits`、`variants`、`reuse_from`；默认供模型带字设计，亦供 Pillow 兜底叠字。 |
| `image_files.csv` | `group,variante,slot,local_path`，路径相对本批次 `images/`，不可使用绝对路径或 `..`。由 `images-collect` 生成。 |
| `images.csv` | `group,variante,slot,url`，网址须为 HTTP(S) `.jpg` 直链，文件名对应槽位；由 `images-urls` 生成。空网址表示尚未托管。 |
| `output/miravia_upload.xlsm` | 用 `shop.json.template` 对应的官方模板填入商品；不会修改原模板。 |
| `output/gpsr/` | `labels/` 下的标签 PNG、预览 JPG、index.csv，以及 `print_A4.pdf`、`generation_report.json`。 |

CSV 以 UTF-8（可带 BOM）读取，输出带 BOM 便于 Excel 打开。带逗号或换行的文本要使用标准 CSV 引号。

## 从条码到候选商品（A2）

首次安装依赖运行 `python -m pip install -r requirements.txt`。仅友购联网命令需要 Playwright；使用系统 Edge，**不要运行 playwright install**。登录资料保存在工作区 `.yollgo-browser/`，不要放进仓库或分享。程序和 agent 不读取密码，用户只在弹出的窗口中输入。

```text
python scripts/mlist.py yollgo-login --ws "E:\店铺工作区"
python scripts/mlist.py fetch --ws "E:\店铺工作区" --batch 冬季一批
python scripts/mlist.py yollgo-search --ws "E:\店铺工作区" --shop 3321 "MANTA BORREGO"
python scripts/mlist.py build --ws "E:\店铺工作区" --batch 冬季一批
python scripts/mlist.py price --ws "E:\店铺工作区" --batch 冬季一批
```

登录命令有界面，登录成功后关闭窗口；其他友购命令无界面，未登录会提示先运行 yollgo-login。只在网页里调用友购 App 自己的函数，不调用签名 HTTP 接口。图片下载只访问公开原图地址。build 和 price 都可离线使用，不依赖 Playwright。

`barcodes.txt` 示例（条码是文字，不能变成科学计数法）：

```text
# 友购里人工选好的两款毛毯
9010186009002  看图拆颜色；有单再拿货
9010186009019  大尺寸
```

重复条码会报行号，需合并为一行。fetch 精确匹配 `bianhao` 或 `usercode`；先选 suppliers 配置顺序靠前的店，都未配置则选最低价。它会保存所有报价，原图以商家和货号命名，避免不同店同 artId 覆盖。

`yollgo.json` 的完整最小例子：

```json
{
  "version": 1,
  "fetched_at": "2026-10-09T14:00:00+00:00",
  "items": [
    {
      "barcode": "9010186009002",
      "note": "看图拆颜色；有单再拿货",
      "offers": [
        {
          "shop_id": "3321",
          "shop_name": "乐家居(瓦伦西亚)",
          "shop_name_es": "H&J TEXHOGAR S.L.U",
          "product": {
            "artId": "1000015560",
            "usercode": "9010186009002",
            "bianhao": "9010186009002",
            "namecn": "MANTA BORREGO 130X160CM AZURITA",
            "namees": "",
            "muluID": "001067",
            "baozhuangshu": 1,
            "precio": 6.5,
            "imageHash": "f8e13d55325363057daa71f7c9317fee",
            "is_attr": 0,
            "attributes": []
          }
        }

      "selected": {"shop_id": "3321", "art_id": "1000015560"}

```

`product` 保留网页的原始商品字段（不包含认证数据）；多店报价继续加到 offers。没找到时 offers 为 `[]`、selected 为 `null`。时间是 UTC。工作区级 `yollgo_shops.json` 按商家 id 保存公开资料 `shopId/name/namees/des/tel/baseurl/imgurl`，反复 fetch 会更新并保留以前的公开条目。

fetch 结尾给中文提醒；`--json` 的 `issues` 包含 `not_found`（条码数组）、`unregistered`（条码和商家）、`zero_price`（条码数组）、`already_listed`（条码、批次、组）、`bulk_minimum`（条码和数量）。已经上过按其他批次的 ean 或 unit_ean 检查，只提醒。起订量大于 1 只提醒，不会自动把整包进货数量变成销售组合装。

## groups.json 完整例子

以下示范同一个条码拆两个颜色，再生成 2 件装。颜色只是格式示例，实际必须看原图、结合能否挑色判断；重量尺寸均为估计。

```json
{
  "version": 1,
  "groups": [
    {
      "group": "G01",
      "var1_name": "Tamaño",
      "var2_name": "Color",
      "packs": [2],
      "notes": "颜色按原图；拿货时核实并称重",
      "items": [
        {
          "barcode": "9010186009002",
          "var1_value": "130x160",
          "var2_value": "Crema",
          "weight_kg": 1.2,
          "len_cm": 35,
          "wid_cm": 30,
          "hei_cm": 10,
          "estimado": true,
          "notes": "原图右侧浅色款"
        },
        {
          "barcode": "9010186009002",
          "var1_value": "130x160",
          "var2_value": "Marrón",
          "variante": "130x160-marron",
          "weight_kg": 1.2,
          "len_cm": 35,
          "wid_cm": 30,
          "hei_cm": 10,
          "estimado": true,
          "pack_measurements": {
            "2": {
              "weight_kg": 2.8,
              "len_cm": 40,
              "wid_cm": 35,
              "hei_cm": 18,
              "estimado": true
            }
          }
        }
      ]
    }
  ]
}
```

- group 是批次内唯一的 `G01`、`G02` 等编号；每个 item 生成一个单件 SKU。同条码可以在同组重复以拆颜色，不能分散到多个组。不同尺寸/货号放在同一 items 数组里，分别写各自 barcode 和变体值。
- var1_name/var2_name 是链接的变体名称。每项填写对应 var1_value/var2_value；有名字就必须有值，没有变体时名称和值都省略或留空，每组仅一个 item。变体取值组合不能重复，var2 不能单独使用。
- barcode 必须是 GS1 校验正确的 13 位字符串，且 yollgo.json 有所选报价。weight_kg、len_cm、wid_cm、hei_cm 必填正数字，estimado 必填布尔值：估计 true，实测 false。程序把估计说明写进候选备注。
- packs 可省略或 `[]`，也可填写 `[2]` 到 `[9]`。每组当前支持一种件数，生成 `G01B`；需要不同件数时请使用不同批次/重新规划链接。组合装默认重量乘件数、长宽不变、高度乘件数；每项可用 pack_measurements 的件数字符串键覆盖整包尺寸和估计标记。
- variante 可省略，自动将变体值转小写、去重音，只留英文字母数字和短横线，自动编号解决文件夹重名；没有可转写文字时用 unico。手填时必须已经符合这个格式并在本组唯一。B 组使用相同变体文件夹名。
- notes 可在组和项填写，会与条码备注、起订包装数合并。未知字段会报错，防止拼错字段被忽略。错误会指出组号和项序号。

build 保持 A1 CSV 表头。颜色拆分的第一项保留原 EAN，其余取原码前 11 位 + 1～9 颜色号 + 重算校验位；撞号换下一个颜色号，用完就停止。unit_ean 始终是原条码。组合装 EAN 为 `2 + 件数 + 对应单件 SKU 条码后10位 + 校验位`，撞号停止。先检查全部原条码，再生成颜色/组合码，和本批次、所有其他批次 candidates.csv 的 ean、官方模板隐藏已有条码及 Pantilla 数据一起查重。

src_name、img_hash、shop、art_id 来自所选友购报价；market_low/high 留空，不跟竞品定价。含 IVA 供应商先除以 1.21，组合装候选的 unit_cost_ex_iva **已经乘件数，是整包成本**。build.json 保存此口径和候选表校验值，让 price 不再重复乘件数；没有 build.json 的旧批次沿用 A1 单件成本算法，结果不变。新批次不要单独复制 candidates.csv 而漏掉 build.json。

同一商家同一货号拆出多个颜色时，后续写 `content.json` 应在该组加 `"sku_include_ean": true`，让每个颜色的卖家 SKU 唯一；B 组默认继承此字段。否则 A1 的 check/fill 会报 SKU 重复，不会生成可上传表。

第一次 build 可填入 new-batch 创建的空表头；已有实际候选行时，必须明确加 `--force` 才覆盖候选表和变体映射。所有校验及撞号检查完成后才写文件。需要修改分组、报价或重量尺寸时改 groups.json（报价需重新 fetch），再 build --force、price；直接编辑 candidates.csv 会导致成本校验不一致并要求重新 build。market_low/high 都可留空，不比较市场价；保留旧市场价的批次仍按原规则输出 vs_market。

离线验收命令：`python tests/test_yollgo.py`，最后应打印 `YOLLGO OK`。真登录真抓取由后续验收完成。

`content.json` 每组条目字段：

| 字段 | 说明 |
|---|---|
| `title` | 西语标题，沿用旧校验长度 55～75 字符；组合装写清件数。 |
| `description` | 西语描述，400～1200 字符，可用 HTML。 |
| `attributes` | 附加属性，最多 200 字符，只填已核实资料。 |
| `warning` | `Sí` 或 `No`，必须匹配模板下拉。 |
| `warning_text` | `Sí` 时用一个或多个 `<li>提示</li>`，不带链接；`No` 时留空；最多 2000 字符。B 组安全提示应和主组一致。 |
| `category` | 模板类目下拉完整原文。由旧 `CATEGORIES` 迁入；用 `categories --search 关键词` 查找。 |
| `gpsr_name` | GPSR 用的商品短名，由旧 `NAMES` 迁入；生成标签时必需。 |
| `gpsr_safety` | GPSR 标签上的 3～5 条西语安全提示数组。由旧 `GENERAL`、旧标签里的缩写提示或现有 warning_text 迁入；不生成新的安全文案。 |
| `sku_include_ean` | 可选布尔值，默认 false。true 时 SKU 含该行 EAN，适用于同货号多颜色；导入器从旧 SKU 规则识别需要的组。 |
| `gpsr_measure_suffix` | 可选标签尺寸后缀，例如原脚本晾衣容量的说明；从旧特殊逻辑抽成数据。 |
| `image_description` | 中文商品外观事实摘要，由旧 Seedream PRODUCTS 迁入；缺时使用原商品名，当前变体附件优先。B未写就继承。 |
| `image_scenes07` | 空数组或四个非空中文场景说明，顺序对应overlays.scenes；无说明用07-a～d核实底图。旧SCENES07迁入，B未写就继承。 |

以 `B` 结尾的组（例如 `T01B`）若未写 `category/gpsr_name/gpsr_safety/sku_include_ean/gpsr_measure_suffix/image_description/image_scenes07`，继承主组 `T01`。显式填写则优先使用自己的值。标题、描述、属性、安全提示不会盲目继承，避免组合装仍声称单件。允许 content 中保留暂未使用的组，校验只检查本批次实际 SKU。

图片规则：主推变体由 `images/<group>/hero.txt` 单行指定，不存在时取候选顺序中的第一个变体。每链接使用主推变体 01～08 展示图；每个变体单独用 `variante.jpg`。目录是 `images/<group>/<variante>/output/miravia-es/v01/`。展示图依次为 `01-principal.jpg`、`02-puntos.jpg`、`03-detalle.jpg`、`04-uso.jpg`、`05-uso-alternativo.jpg`、`06-medidas-contenido.jpg`、`07-usos.jpg`、`08-modelo.jpg`；GPSR 图不放入展示图。

其他命令：

```text
python scripts/mlist.py import-legacy --from "旧项目目录" --ws "新工作区" --batch 迁移批次
python scripts/mlist.py categories --ws "工作区" --search manta
python scripts/mlist.py gpsr --ws "工作区" --batch 批次
python scripts/mlist.py overlay --ws "工作区" --batch 批次 --all
python scripts/mlist.py overlay --ws "工作区" --batch 批次 --group T01 --demo
python scripts/mlist.py images-collect --ws "工作区" --batch 批次
python scripts/mlist.py images-urls --ws "工作区" --batch 批次 --base-url https://example.test/images
```

`import-legacy` 把旧 data 中 CSV/JSON/TXT 复制进**新批次**，将代码常量并入 content；制造商使用 shop.json，不另存 fabricantes.json。工作区缺少已配置模板时从旧 template 复制同名文件。不会覆盖已有批次或店铺配置。Windows 图片用 junction（无需管理员），其他系统用目录符号链接；联接中的图片只读，收集不会补写变体图，overlay 会拒绝写入联接。请改用新批次普通图片目录后再处理图片。

旧代码曾把 GPSR 限制为固定 60 SKU，本次已去掉。若旧组原本就没有通用安全提示（例如部分后来新增组），导入会保留空 `gpsr_safety`；`gpsr` 会明确要求补齐，不擅自推断。

`--json` 的 stdout 始终是一个对象，至少含 `ok`、`warnings`、`errors`；正常退出码 0，错误非 0；Seedream 未加 --yes 或 --auto 时退出码2、needs_confirm=true。帮助也可通过 `--help --json` 取得 `help` 字符串。错误和提醒是中文字符串数组，可能附有模板原文、路径和底层诊断。

## 图片步骤（A3）

规则在 `出图规则.md`、`文案规则.md`，可独立阅读，不依赖旧项目。下面五命令也接受--ws/--batch/--json。

|命令|参数及行为|
|---|---|
|images-plan|--mode model-text（默认）或base-overlay；写批次根image_plan.json及image_plan.md，按组打印缺/已有/重做。旧图片联接可只读规划。|
|images-finish|可--group多次或--only完整id列表；处理internal/raw中槽位前缀png/jpg/jpeg，按mtime选最新，安装前备份internal/old；06脚本画、variante从01派生、B共用位置复制。重跑无变动不重复备份。|
|seedream|必须--only完整id列表或--all-missing；先显示张数及estimated_units，--yes才读Key/联网。派生/共用不扣费，已有raw未要求重做时跳过。按当前数据校验计划是否过期。每id累计最多两次，日志seedream_log.json在批次根；失败先查控制台，程序不自动重试。|
|images-sheet|--name名字（默认review）、--group多次、--only完整id、--pending；生成批次根review/名字.jpg，大批量自动-1/-2分页；缺图也占格并写状态。|
|images-review|--ok完整id列表、--redo完整id列表及--note原因；写批次根image_review.json，不是图片目录。通过仅针对当时成品字节，图片变化后自动失效；重做须再审才能解除。|

image_plan.json含version、mode、jobs、summary。每job字段：id（组/变体/槽位）、group、variant、slot（01～08或variante）、output、raw_dir、raw、refs、method、source_id、prompt、status（missing/existing/redo）、reason、reviewed、blockers、pack_qty。路径相对批次，不含绝对路径或..；图片联接可以读取参考图，写命令拒绝联接。method为model/model-text/base-overlay/script/derive/copy；script表示模型只生成无字06底图，后续脚本画数字；derive/copy不需模型。展示图只规划主推变体，其他变体规划01/variante；finish同时维护B组每个登记变体的共用成品。

image_review.json为 `{ "version": 1, "reviews": { "G01/crema/02": { "result": "ok", "note": "", "sha256": "文件摘要", "at": "UTC时间" } } }`。redo的note必填，status按当前磁盘推导审过/没审/要重做，旧通过记录与新文件不匹配时视为未审。06数字来源为src_name里的明确CM/L/ML和pack_qty，候选表len/wid/hei不用于图上本体尺寸。

stock_fotos.csv在批次根，字段 `archivo,fuente,url,autor,licencia,usado_en`；archivo相对批次，fuente=Pexels/Unsplash，usado_en为完整id，多个用空格/分号。旧素材映射可保留但需人工对上新id及许可；缺真人记录在清单blockers中，不擅自付费生成真人替代。

离线测试：`python tests/test_images.py`，应打印IMAGES OK，接口为假图，不读真实Key、不联网。

### 全自动出图日志和早晨报告（A5）

`seedream --auto --only 完整id...` 或 `--auto --all-missing` 按店铺预算运行，与 `--yes` 互斥。结果增加 `spent_units`（本批全部尝试累计）、`budget`（budget_units_per_group/budget_units_per_batch）、`over_budget`（本次超预算 id 列表）。超预算跳过退出 0，有 errors 则非 0。

`seedream_log.json` 继续以完整 id 为键、尝试数组为值。每条新尝试保存 `attempt`、`state`（started/saved/failed）、`units`（该次估算单位）；saved 另有 `raw`。不论 state 都计费；旧记录缺 units 按 1.36。根对象另有可选 `over_budget` 数组，累计记录曾因预算跳过的 id，不是尝试、不计费用、不占两次限制。不要删日志来重置预算。

```json
{"G01/crema/01": [{"attempt": 1, "state": "failed", "units": 1.36}], "over_budget": ["G01/crema/02"]}
```

`mlist report --batch 批次 [--json]` 只写批次根 `早上看这里.md`，不调用 finalize，不更新表、图片或台账，不联网。复用 status 新旧判断、check 和发布记录核验，`upload_ready` 为真才写可以上传。分表存在且属于当前完整表时列分表，完整表留作备份；售价/每单利润取 priced.csv 的 price/profit_with_coupon，审阅计数取 status。JSON 同时给出 outputs、groups、count、prices、spent_units、group_units、over_budget、image_review、image_problems、todos、notes。

`check` 和 `fill` 共用校验，先尽量汇总独立问题。缺文件等无法继续的依赖会报明路径；合法但尚未托管的图片仍按旧流程允许填表，使用友购占位网址，并给出提醒和 `upload_ready:false`，不是可以直接上传。`check` 还会提醒清单中的本地图片是否缺失；它不联网检测直链。`status` 仅根据文件内容和修改时间推导 `exists/ready/fresh/newer_inputs`，不写状态文件。

模板字段对照集中在 `scripts/listing_core/headers.py`。可见列按 Pantilla 第 1 行表头定位，库存允许 `<br/>` 店名后缀；隐藏下拉按模板内部字段标识定位，两者不用同一固定列号。遇到缺失或重复的必用表头即停下；未知额外列不填写。写入只改 Pantilla 的 sheetData 和 dimension，其他 ZIP 成员解压后的字节、宏、校验和原 1～4 行完全保留，并在替换输出前再次验证。

## 发布图片和最终表（A4）

```text
python scripts/mlist.py image-host-setup --repo 账号/仓库名 --ws "工作区"
python scripts/mlist.py publish-images --ws "工作区" --batch 冬季一批
python scripts/mlist.py publish-images --ws "工作区" --batch 冬季一批 --yes
python scripts/mlist.py finalize --ws "工作区" --batch 冬季一批
python scripts/mlist.py finalize --ws "工作区" --batch 冬季一批 --max-groups 5 --json
```

setup 和 publish 不加 `--yes` 时只读预览、不调 Git/gh、不联网、不写文件，退出码 2，JSON 有 `ok:false`、`needs_confirm:true`。publish 列出图片 id、张数、字节数、目标仓库和每张跳过原因。默认只发布 `image_review.json` 中 result=ok 且 sha256 仍与当前字节相同的图。`--include-unreviewed` 明确放宽审阅门槛（也包括已标记重做的图），仍需确认 `--yes`；缺图始终跳过。只取主推款 01～08 和所有登记变体的 variante，不上传 GPSR、原图、历史备份和未登记目录。

公开路径为 `<批次slug>/<组slug>/<变体slug>/<标准文件名>.jpg`。前三段统一采用：原名称 NFKD 去重音 → 去掉非 ASCII → 转小写 → 非字母数字合并为短横线 → 保留前 40 字符（去掉末尾短横线）→ 空串用 batch → 追加 `-` 和**原名称 UTF-8 SHA-256 前 16 位小写十六进制**。大小写、中文及重音原文都参与摘要，所以不同原名即使可读部分相同也有不同目录，摘要碰撞概率极低；同一原名可稳定复现，不依赖系统语言和运行时间。文件名沿用 01-principal.jpg 等及 variante.jpg，路径仅含小写 ASCII 字母、数字、短横线、斜线和扩展名的点。

内容改变采用**同路径覆盖**：便于长期保留网址、避免累积版本图；仅变化的图片产生提交，无变化不再提交或推送。发布前拉取远端并仅快进同步，保留 README、旧批次和其他内容，不使用 force。重复发布仍会重做网址抽查。GitHub/CDN/Miravia 可能缓存同网址旧图；新发布后先确认前台刷新，不能承诺缓存立即失效。

推送成功后原子写 `images.csv`（`group,variante,slot,url`）及 `image_publish.json`（version、host、files 中的路径/摘要/审阅状态、commit、checks）。仅写此次选择成功推送的图，不混入之前跳过的旧网址。均匀抽查最多 5 条（不足时全查），要求 HEAD 200 且 Content-Type 为 image/*。抽查失败时保留已推送网址和诊断，但命令退出非零；检查网络或图床后重跑，不自动重试。发布报告只有当前已选图的摘要，finalize 会阻止报告中的图被修改、删除、配置/网址发生变化或抽查未通过后宣称可上传。

finalize 全程离线：只读图片收集 → 直接使用 publish 已写的网址 → fill → check。已有非 GitHub 的 images.csv 也可直接用；手动托管流程可指定 `--base-url` 从本地清单生成网址（这是对已托管的声明，程序不会代上传或联网验证）。已有发布报告时不允许 --base-url 覆盖。没有网址可出草稿，友购占位链接会明确阻止 `upload_ready`。制造商/负责人不在模板下拉或有其他错误时失败且保留原表；所有提醒处理完才 `upload_ready:true`。本地缺主图/变体图、展示图网址不齐、旧价格等也保守阻止可上传。JSON 始终含 upload_ready；中文输出逐条说还差什么及表路径。

`--max-groups N` 按实际链接数（不同 group）装入每份 `output/miravia_upload_1.xlsm`、`_2.xlsm` 等；主组和 B 组各算一个链接，作为一个家族不可拆开。若 N=1 放不下含 B 的家族则报错，要求至少 2。默认不拆；拆分时完整 `miravia_upload.xlsm` 留作备份，**只上传输出列出的分批表**，不要同时上传完整表。重跑清理多余编号分表。每份都沿用官方 ZIP 复制与宏/校验保护，不经过 openpyxl 保存。

可上传时更新工作区根 `台账.csv`（带 BOM）：`日期,批次,组,变体,EAN,卖家 SKU,批发商 id,友购货号,进价,实际成本,售价,每单利润`。按批次+EAN 覆盖，原日期保留，其他批次不动；同批次已删掉的 SKU 移出台账。进价取 priced.unit_cost_ex_iva（不含税原报价；A2 B 组为整包进价，旧 A1 为单件进价），实际成本取 real_cost，每单利润采用保留优惠券后的 profit_with_coupon。台账意味着表已准备好，不表示已在 Miravia 提交成功；不可上传或校验失败时不更新。

离线验收：`python tests/test_publish.py`，末行 `PUBLISH OK`。只用仓库 .tmp 下本地 bare Git 仓库，GitHub CLI/HEAD 抽查替换为假接口，绝不访问真实图床。
