# Miravia 西班牙站出图规则

这是本店执行标准，agent 可独立照做。图片事实来自当前原图、用户确认或核实同款资料；生成图、旧 AI 文案及相似款不能证明规格。本次固定八个展示位置，覆盖旧五图/六图默认方案；缺事实时用能确认的内容把图做完(全自动模式不停下来),不用重复图凑数。

## 商品与文件

看实际参考图，按型号、颜色、尺寸、售卖数量归组。图里有几件不代表卖几件，场景道具不是赠品。原图/来源映射和事实记录留 internal/，交付只含成品及简短待补问题。商品/原图有品牌、logo、卡通/IP 图案或“同款”时，分组就提醒用户决定是否上架。功能和卖点可用原图看得到的、`research.json` 里外观一致同款(`same: true`)写到的;认证标志、疗效、同款资料里也没有的具体数字不补造。同类爆款普遍宣传的好处，只要本商品看得出有对应部件就能写（带滤芯可写 filtra cloro y cal、agua más suave）；禁认证标志、医疗/治疗说法、别家品牌，不补无依据具体数字。看不见的内部结构不画剖面或彩色颗粒。

先做好每个变体01，核对原图颜色、轮廓、结构、真实图案、件数及缩略图，再扩展主推款。后续调用实际附上认可的本款主图及细节/人物素材，不能只在prompt写文件名。content可写structure_lock中文锁定结构和数量，进入所有模型槽位。04/05/07/08除主图外附一张能看清结构的正视/俯视原图，优先变体internal/base/structure.jpg，主推可用组级同名原图，没有时用本变体src原图；agent先核实视角，不把生成图当结构原图。附件角色明确“图N锁定结构和隔板数量”。外观摘要可能描述旧主推色，当前变体附件优先。可改善布光、背景、透视；颜色不要过度美化，不把哑光变镜面，不修掉真实缺陷。参考图叠加中文、价格、水印去掉；本体真实标签、logo、条码、QR和印字保留，不翻译，不重绘假码。默认去外盒、吸塑、吊牌，保留瓶身、喷头、必要盖子及本体标签。

成品 **1200×1200、sRGB、JPG，严格小于3,145,728 bytes（3 MiB）**，不是十进制3 MB。非方图用白边适配，不拉伸商品。这是店铺保守规格，不宣称平台最低要求。检查通过不等于平台审核通过。

01/variante导出时规范白底：仅将RGB每通道≥245且与图像边缘连通的近白像素置为#FFFFFF，保持较深柔和阴影和商品内部不连通的近白细节；不用整图阈值去白，不需要为近白背景重复付费。

展示图在 `images/<组>/<主推变体>/output/miravia-es/v01/`。主推读 `images/<组>/hero.txt`，无文件时用候选顺序第一个。每个其他变体只需自己的01和variante.jpg；变体图从本变体01派生，白底无新增字。

## 同步到速卖通

商品会从米拉维亚同步到速卖通西班牙(流量更大),图片同时按速卖通的习惯做:
- 速卖通主图一般只显示前 6 张,所以 01～06 要自成一套:01 白底干净、02 卖点、03 主打卖点特写、04 使用、05 场景、06 尺寸/内容。
  07 拼图和 08 结果图也可出现在描述里；finalize默认按08/03/04/07插图，结果图在开场后，03在卖点后，关键词在最后。
- 01 速卖通要求干净:纯白底、无字、无水印、无边框、不拼图,商品占满画面。
- 速卖通买家大多用手机看小图:图上的字要大、少(标题 ≤6 词),一张图只讲一个卖点,远看也能看清商品。

## 文字、尺寸与真人

- 默认图像模型把照片、文字、图标一体设计。新增字只用当前组/变体overlays.json文字，一字不改；字母、重音、大小写、数字逐字校对，错一个也重做。标题≤6词，大号粗体无衬线、深灰/深蓝高对比；场景文字放顶部半透明浅色横条，不压商品/人脸。04/05/08场景和标题不同。
- **06一律无字底图＋脚本**。尺寸只用商品原名明确CM、核实实测或 research.json 里 `same: true` 同款写明的尺寸，不用candidates估计包裹长宽高；容量只用明确L/ML。无确认尺寸只写内容。共用目录多种本体尺寸不画统一箭头；宠物衣尺码、晾晒容量3m不作长宽。检查端点与方向，必要时06配置product_box填核对过的0–1边界，脚本不能判断透视是否合适。
- 默认一律 Seedream 出字和画面一体的设计图(model-text),不要自己切换模式。兜底 `images-plan --mode base-overlay` 只在 Seedream 连续好几张都把字写错时整批改用(记进 notes.md)：无字底图＋脚本叠字。`mlist.py overlay --all`处理internal/base既定底图；images-finish也处理清单无字raw图。07可以四张底图，或生成一张无字四格底图后标字。01/variante永不新增字。
- **场景图要让人联想到买了能得到什么**(店里 95 分的链接:paellera 的图里盛满海鲜饭,mortero 旁边摆着做好的酱和菜):04/07/08 拍出结果和享受的画面(花洒:舒服地淋浴、头发顺滑),这些图也会被插进描述。
- **场景要合常识**:04/05/08 按 content.json 的 `scene_briefs` 写清位置/动作/必要连接/可见结果，07每格也写清这四项；全部符合 `use_scene`(花洒连着软管在淋浴区出水,不能出现在镜子/洗手台前;门挡条装在门底;毯子盖在沙发/床上)。挑真人素材时就挑场景对得上的(要淋浴就找淋浴间里的人,不要找站在洗手台前的);02/03 重点表现 `hero_feature`(如透明手柄里可见的滤芯外壳，不画看不见的内部)。AI 自审时场景不合常识算不合格。
- 按每张/每格是否有人选择附件（含07）；无人使用或结果场景不强加人物。真人只用Pexels/Unsplash下载文件作为实际附件；合成保持素材人物身份和脸；背景按本槽位scene_briefs生成，不锁素材房间，商品与环境统一生成、自然融合。脚本不抠图贴商品冒充生成。批次根stock_fotos.csv记 `archivo,fuente,url,autor,licencia,usado_en`；archivo相对批次，usado_en用完整清单id，多个用空格/分号。许可和构图适用须核对，欧洲风格不是国籍证明。缺素材先补，旧底图来源也须核对；不把生成脸当真人。不宣称合成图为真实产品拍照。宠物类突出宠物与商品。
- 每张最多初次生成＋一次具体修正；仍失败记录问题、补素材，不无限抽卡。Seedream每id累计两次预算，不确定网络失败也记一次，先查控制台扣费，不自动重试。

## AI 自审(全自动模式代替用户审图)

images-finish 后每张都打开原尺寸和320px缩略图；拼图只看全貌，逐字核对必须打开单张。
- 商品结构/颜色/件数错误、必要连接缺失、用途错误、文字与overlays不符、禁用认证/医疗说法或别家品牌、虚构不可见内部、尺寸箭头错误，任一项不通过。卖点依文案规则大胆写，不把“没有检测报告”当成禁止品类常见好处的理由。
- 对照原图和structure_lock逐项计数：格数及长/短格分布、按钮数、售卖件数及固定隔板位置。写明“原图5格，成品6格”等证据，任一数量不符即redo；遮挡看不全无法逐项确认也不通过，不能用“整体看起来差不多”放行。
- 02/03必须能指出主卖点在哪里；04/05/08必须能指出动作、连接及结果。遮挡导致无法判断也不通过。
- 人物、手部、商品尺度和接触自然；01/variante纯白无新增字。轻微背景瑕疵可记录后通过。
- 合格用images-review --ok；不合格用--redo并写具体修正。可加--checks（原尺寸、320px缩略图、文字等）、--evidence（可见证据）、--severity minor/major/critical。major/critical不能通过。
- **两次失败保留redo失败状态，不发布；不得改成通过凑数。** 补素材后另行人工处理，不无限扣费。失败/八图不齐的组只出miravia_draft.xlsm，其余组继续。publish的--include-unreviewed也不能放行失败组；报告列出草稿组及原因。
- 重做备注写一条完整可执行的修正方案：场景图写清新位置/动作/连接/结果和取景，替换旧场景与构图；其他图写新的构图/外观要求。不要只写“重做一次”。固定的身份与商品参考仍保留。

## 命令

```text
python scripts/mlist.py images-plan --batch 批次
python scripts/mlist.py seedream --batch 批次 --only G01/crema/02
python scripts/mlist.py seedream --batch 批次 --only G01/crema/02 --yes
python scripts/mlist.py images-finish --batch 批次
python scripts/mlist.py images-sheet --batch 批次 --name primera --pending
python scripts/mlist.py images-review --batch 批次 --ok G01/crema/02
python scripts/mlist.py images-review --batch 批次 --redo G01/crema/02 --note "颜色偏了"
```

都可加--ws、--json。agent直接读image_plan.md，把原始图放 `images/<组>/<变体>/internal/raw/<槽位>-v01.png|jpg`，修正版v02。finish在安装前备份internal/old，不覆盖早期备份；自动画06、派生variante、复制B共用图。通过绑定文件SHA-256，换图再审。清单/审阅/拼图在批次根image_plan.json/.md、image_review.json、review/，不写旧图片联接。旧联接只读，写图片命令要求普通批次图片目录。

Seedream走BytePlus国际版5.0 Pro，1440×1440原图再导出1200。按旧Starter口径估算每张1.36单位，从第二张参考起每张0.09；不是永久价，以账户控制台为准。未加--yes只打印张数与单位，退出码2、needs_confirm=true，不读Key、不联网。Key只读ARK_API_KEY进程/Windows用户环境变量，不入文件。本店出图一律走Seedream API，不用Codex/GPT自带出图。先做01再更新清单，不把尚无主图的整套交给付费接口。

接口与模型ID核对来源：[BytePlus官方Seedream 5.0 Pro文档](https://docs.byteplus.com/en/docs/modelark/seedream-5-0-pro)。套餐单位来自原项目用户确认口径，不能用API文档代替账户套餐核对。

## GPSR

mlist.py gpsr按店铺与商品事实画平面标签PNG/A4，打印贴货。制造商/负责人取shop.json中实际确认及后台登记资料；旧店批发商口径不代表每家店身份相同，不能编邮箱。尺寸/材质无依据省略。非电器不放WEEE或装饰性CE。

贴在商品/包装上的效果图单独放output/gpsr/v01，明确“模拟效果图”，不伪称实拍或合规证明，标签字保持脚本原版。真实背面/包装证据必须相机拍摄，不能生成替代。GPSR不进八图或variante。

## Prompt模板（填真实事实，实际附图）

只给模型本图视觉指令，顺序：本图目标 → 参考图用途 → 当前变体事实 → 动作/连接/结果 → 镜头构图 → 西语排版。目标约300中文字符以内，西语原文不截断。空副标题整句删除。

make_plan先收集{path, role, use}，筛选去重再编号；同一列表生成API附件和“图1/图2…”用途。文件路径、来源登记、重试/导出限制、其他槽位要求和重复JSON均不进入prompt。只给当前图有用的主图/细节/人物附件，不默认加供应商整页。必要连接（如花洒软管）可作为环境道具，不能被“只展示随货内容”误删；也不表示赠送。

01：纯白1:1主图；当前售卖N件，完整分开可数，组合最长边80%～85%；轻侧角、柔光和薄接触阴影。去销售包装，保留本体印刷。无新增文字图标。

02：1:1卖点图；第一眼突出hero_feature；按已审主图（缺时原图）的商品宽高比适配：宽扁商品采用上方图标、下方整宽商品区；方形/竖长商品用左侧图标、右侧商品区。商品等比完整放入该区，宽高上限必须同时满足，四角完整、四周≥5%安全边距；N件分开可数。浅底侧光，大号标题、可选副标题，文字避开商品。不同时要求窄商品区和大于区宽的最长边。

03：1:1主卖点部件特写；部件约占60%，保留邻接结构定位，近摄侧光、背景微虚，允许局部出画，不要求完整件数。不画不可见内部/剖面/彩色颗粒。zoom仅在03展开：默认不加圈；仅true且有真实macro附件时，一个小白边圈指向该附件编号。

04：1:1操作近景；填本图location/action/connections/visible_result；有人时只露手臂，斜侧近景，商品最长边约55%，靠近镜头取景并保持真实手部比例；软管等必要环境连接允许出现，接触/作用方向一致；顶部标题、可选副标题。

05：1:1生活使用图；写本图具体地点/动作/连接/结果，不写“不同于04”；有人时肩以下/背影不露脸，中近景，商品35%～50%，焦点落商品与作用处，尺度真实；顶部西语留白。

06：1:1无字尺寸底图；N件确认随货内容分开完整，正面或俯拍，中央70%，留15%标注空间；比例按附件，轮廓清楚。不画新文字、数字、箭头、尺寸线和图标；脚本后续绘制尺寸内容，不附尺寸字典。

07：1:1四格2x2或1+3，细白线；逐格明确阅读顺序、位置/动作/连接/可见结果和标签。实际使用件数与销售数量分开；主体约半格，光色统一。有人格才附人物素材，可用完整id加-1～-4登记；同文件去重合并用途。总标题和各格标签逐字照抄。

08：1:1生活结果图；写真实位置/动作/手持或安装连接/可见结果；有人时保留真人身份和脸，正脸或轻侧正脸、自然表情。中近景，商品30%～45%，人物商品共同居中、尺度真实，关键部件不遮挡；顶部标题与可选副标题。

带字图统一：只绘指定西语，重音和大小写一致、少而大、放留白、不重复、不加其他文字/认证标志/emoji。01、06和base-overlay只要无字底图。

## 付费前预检

每次付费前先运行 `mlist preflight --batch 批次`。只读检查模板存在、供应商已配置且制造商/欧盟负责人在模板下拉、类目、图床、ARK_API_KEY是否设置，以及配置预算余额。只判断Key存在，不取值；预算为上限减本地尝试记录，不联网查询真实账户。账户问题停止付费步骤，组问题只跳过该组，job blocker只跳过该job并记入seedream结果。先补齐use_scene/hero_feature/scene_briefs，B组继承；01未通过不得扩展。
