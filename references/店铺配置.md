# 店铺配置

每人使用自己的工作区和 `shop.json`，不要把实际工作区放进 skill 仓库。首次运行 `python scripts/mlist.py init --ws "工作区路径"` 会复制 `config/shop.example.json`；再次运行不会覆盖已有配置。

示例保留原店的现值，方便迁移对拍。妹妹开店时需要换成自己的模板和登记信息。除 `price_includes_iva` 外，列出的字段都是必填；缺项会明确报出 `shop.json.xxx`。供应商列表可以只保留自己使用的商家，填表前候选中的商家必须配置。对象中的顺序就是 fetch 的选店优先顺序。

| 字段 | 是什么、怎么改 |
|---|---|
| `pricing` | 定价参数对象，金额单位欧元。修改后重新运行 `price` 和 `fill`。 |
| `pricing.cost_factor` | 不含税报价转实际进货成本的倍数。示例沿用旧店 1.262；按自己实际成本口径修改。 |
| `pricing.packaging` | 每单包装成本。填写非负数，单位欧元。 |
| `pricing.fees` | 平台费率对象。下面三项分别填写小数，例如 12.3% 写 0.123。 |
| `pricing.fees.commission` | 佣金率。根据自己账单修改。 |
| `pricing.fees.points` | 积分费用比例。根据自己账单修改。 |
| `pricing.fees.promo` | 推广计划等费用比例。根据自己账单修改。 |
| `pricing.coupon_rate` | 预留优惠券扣款比例。费率与优惠券比例合计必须小于 1。 |
| `pricing.min_profit` | 每单最低目标利润，非负数。目标利润取它与成本乘 `profit_rate` 的较大值。 |
| `pricing.profit_rate` | 成本的目标利润比例。30% 写 0.30。 |
| `pricing.spread_warn` | 同一链接最贵/最便宜 SKU 超过多少倍时提醒。仅提醒，不自行改价。 |
| `pricing.ship_tiers` | `[[计费重上限kg, 运费欧元], ...]`，重量上限严格递增。超出最后一档时沿用最后一档费用，与旧逻辑一致；应按真实运费更新。 |
| `pricing.volumetric_divisor` | 体积重除数，体积按厘米计算。计费重取实重与长×宽×高÷此数的较大值。 |
| `pricing.original_markup` | `original_price` 相对于售价的倍数。旧店为 1；当前填表流程要求原价等于售价，不填写折扣价格。 |
| `stock_default` | 表内默认可售库存，允许 0，必须是整数。它不是实物盘点库存。 |
| `brand` | 填入模板的品牌原文。无品牌商品按示例使用 `Sin marca`。 |
| `template` | 工作区 `template/` 下的官方 `.xlsm` 文件名或相对路径。换店铺或登记新公司后，从自己后台重新下载模板。 |
| `sku` | 店内 SKU 的命名配置对象。修改会改变输出 SKU，旧批次请谨慎处理。 |
| `sku.prefix` | SKU 前缀，只用字母数字。后面自动接商家、货号，按批次设置可追加 EAN，组合装再加 `-P件数`。 |
| `suppliers` | 以友购商家 id 为键的对象。id 必须保留字符串形式，如 `"027"` 不能改成 `27`。 |
| `suppliers.<id>.company` | GPSR 标签用的公司名。照自己确认的供应商资料填写。 |
| `suppliers.<id>.address` | GPSR 标签用的完整公司地址。过长导致标签放不下时会报错，请核对排版和合法简称。 |
| `suppliers.<id>.email` | GPSR 标签用的联系邮箱。示例逐字保留旧配置，并不代表程序核验过邮箱。 |
| `suppliers.<id>.fabricante` | 模板制造商下拉完整原文，包括编号和日期；不要只填公司名。 |
| `suppliers.<id>.responsable` | 模板欧盟负责人下拉完整原文。程序会对照模板检查，和制造商使用不同编号。 |
| `suppliers.<id>.price_includes_iva` | 可选布尔值，省略等同 false。true 表示友购报价已含 IVA，build 先除以 1.21；组合装再乘件数。不要根据最低价猜测是否含税。 |
| `image_host` | 为后续图床任务预留，当前填 `null`；本次不上传图片。当前网址生成使用 `images-urls --base-url`。 |

商家 `6850` 的示例资料按任务包沿用 ZHENGDA COMERCIO。导入旧数据不会覆盖已有 `shop.json`；发现旧制造商原文和配置不同会提醒你手动核对。

A2 示例新增旺达 `2822`，标记 `price_includes_iva: true`，其公司、地址、邮箱及两个模板下拉使用明确的待填写提示。请核实后填写；未使用旺达时可以从 suppliers 删除这一项。示例不是已审核的制造商资料。税字段只影响 build，不会追溯修改旧 candidates.csv 或改变旧批次的定价结果。

```json
{
  "suppliers": {
    "2822": {
      "company": "请填写核实后的公司名",
      "address": "请填写核实后的地址",
      "email": "请填写核实后的邮箱",
      "fabricante": "请填写模板制造商下拉完整原文",
      "responsable": "请填写模板欧盟负责人下拉完整原文",
      "price_includes_iva": true
    }
  }
}
```

上面是字段片段，不是完整 shop.json。`fetch` 会查询已配置商家（按顺序），然后查询其他关注商家；多家报价全部保留。未配置商家只能作为暂时选中的报价，程序会提醒制造商为空，fill 前仍须补齐配置。公开商家资料保存在工作区 `yollgo_shops.json`，可用于后台登记时参考，不会自动编造邮箱或登记资料。

工作区选择顺序：命令行 `--ws` → 环境变量 `MIRAVIA_WS` → 用户目录下 `.miravia-listing.json` 的 `workspace` → Windows 系统已知的“文档”文件夹下 `Miravia工作区`。Windows 文档目录由系统 API 查询，支持已搬家到其他盘的文档目录；不会拼接 `%USERPROFILE%\Documents`。非 Windows 使用 `~/Documents/Miravia工作区`。
